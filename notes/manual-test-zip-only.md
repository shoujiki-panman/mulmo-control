# 実機テスト手順 — zip だけで使い始められるか（#15）

対象: v1.0.18 以降
所要: 20〜30分

机上で潰せるところは潰してある。ここに残っているのは**人が触らないと分からないこと**だけ。

---

## 事前に分かっていること

### Gatekeeper に弾かれる（確認済み）

ブラウザで zip を落とすと隔離マークが付き、ダブルクリックでは開けない。実測値:

```
隔離マーク : 付く（com.apple.quarantine）
判定       : rejected
署名       : adhoc（自己署名。Apple Developer ID ではない）
```

**これは想定内。** 回避は「右クリック → 開く」。この手順が実際に通るかを見るのがテストの一部。

### 事前に潰した障害物

- #11 補助スクリプトをアプリに同梱
- #12 LaunchAgent をアプリが書く
- #51 MulmoTerminal のボタンも同梱版を呼ぶ（`~/.local/bin` 依存を除去）

`~/.local/bin` が空の状態で、status の実行・兄弟スクリプトの解決・LaunchAgent の生成が通ることは確認済み。

---

## 準備

**別のユーザーアカウントを作るのが一番きれい。** 自分のアカウントには `~/.local/bin` も `~/Documents/Codex/` も既にあるので、素の状態を再現できない。

`システム設定 → ユーザとグループ → ユーザを追加`

作れない場合は、退避でも代用できる（テスト後に必ず戻す）。

```bash
mv ~/.local/bin ~/.local/bin.bak
mv ~/Documents/Codex/SwiftBarTools ~/Documents/Codex/SwiftBarTools.bak
```

---

## 手順

### 1. zip を落とす

ブラウザで開く（`curl` では隔離マークが付かないので、テストにならない）。

https://github.com/shoujiki-panman/mulmo-control/releases/latest

`MulmoControl.zip` をダウンロード。

- [ ] ダウンロードできた

### 2. Applications にドラッグ

- [ ] `/Applications` に置けた

### 3. 開く

まずダブルクリックしてみる。**弾かれるはず。**

- [ ] 何と表示されたか: ______________________

次に**右クリック → 開く**。

- [ ] 開けた / 開けなかった
- [ ] 何回クリックが必要だったか: ______

> ここが「ターミナル不要」を名乗れるかの分かれ目。文言が分かりにくければ、README に手順を書くだけでは足りないかもしれない。

### 4. メニューバーのアイコンを探す

- [ ] 見つかった / 見つからない
- [ ] 探すのにかかった時間: ______

### 5. MulmoTerminal を入れる

`環境` タブ → 未インストールのはず → `インストール`

- [ ] 表示は「未インストール」だったか
- [ ] インストールが通ったか
- [ ] かかった時間: ______

### 6. MulmoTerminal を操作する

`運用` タブで順に押す。**#51 で直したところ。**

- [ ] `開く` — ブラウザが開く。タブは1つだけか
- [ ] `再起動` — 動く。タブが開かないこと
- [ ] `停止` — 止まる
- [ ] `起動` — 上がる

### 7. 常駐（#12 で直したところ）

`環境` タブの `ログイン時起動・落ちたら再起動` が `オン` になっているか。

- [ ] オンになった

```bash
# 定義ファイルが作られ、アプリの中を指しているか
/usr/libexec/PlistBuddy -c 'Print :ProgramArguments:0' \
  ~/Library/LaunchAgents/com.shutanuma.mulmoterminal.plist
```

- [ ] `/Applications/Mulmo Control.app/...` を指している
- [ ] `停止` を押すと解除される

### 8. 再ログイン

ログアウト → ログイン。

- [ ] MulmoTerminal が自動で上がった

## 判定

上が全部通れば #15 は達成。**ただし手順3で詰まるなら、それは「ターミナルは要らないが、右クリックの知識は要る」状態。** そこをどう扱うかは別の判断になる。

選択肢:

- README と初回ダイアログに右クリックの手順を書く（費用ゼロ、利用者に一手間）
- Apple Developer Program に入って署名 + notarization（年 99 USD、利用者は素直に開ける）
- 当面は前者、外部の利用者が増えたら後者
