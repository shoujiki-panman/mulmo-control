# 週報

## 何であるか

- 出す先は **`SingularitySociety/bootcamp004`**。ファイルを足して PR を作る
- PR の題名は **`週報 YYYY/MM/DD — 名前`**（日付は出す日。直近は 2026/09/04 の PR #650）
- 概ね週1回、木〜金に出している。期間は **前回の週報の翌日から出す日まで**

## 手順（この順に。飛ばさない）

1. **前回の週報を読む。** Gmail で `subject:週報 bootcamp004` を検索して直近の PR 番号を取り、bootcamp004 でその PR のファイルを読む。置き場所（ディレクトリと命名）と見出し・文体をそのまま踏襲する
   - **bootcamp004 は mulmo-control 起点のセッションには足せない**（別オーナーのリポジトリは `add_repo` で追加できない。2026-09-17 に実測）。週報は **bootcamp004 を起点にしたセッションで書く**。mulmo-control のセッションで頼まれたら、材料（手順2）だけ集めてチャットに出し、「PR は bootcamp004 のセッションで作る」と言って止まる。形式を想像で作らない
2. **材料を集める。** 前回の週報の翌日から今日までの
   - mulmo-control: `git log --since=<前回の翌日>`、閉じた Issue、マージした PR、Releases、`STATUS.md` の追記
   - bootcamp004 の他の活動があればそれも（前回の週報に何を書いていたかで判断）
3. **下書きをチャットに全文で出す。** 前回と同じ見出し構成で。個人名を書かない
4. **承認を待つ。** 直しの指示があれば直して、もう一度出す
5. 承認が出てから: bootcamp004 に前回と同じ置き場所でファイルを足し、ブランチを切って PR を作る。題名は上の形式。本文は前回に合わせる
6. PR の URL を報告する

## やってはいけないこと

- mulmo-control にファイルとして置く（`notes/` などに書かない）
- 承認前に commit / push / PR
- 前回の週報を読まずに見出しを決める
